# 제미나이에게 작업 맡기기

Claude가 직접 큰 파일을 쓰면 토큰이 많이 든다. 아래 순서로 **지시는 Claude, 작성은 제미나이, 검토는 Claude**로 나눈다.

## 맡겨도 되는 일 / 안 되는 일
- 맡긴다: 디자인 시안(`docs/design/`), 반복적인 정적 HTML·문서 초안, 정해진 틀에 맞춘 파일 여러 장.
- 맡기지 않는다: 앱 코드(`web/`, `src/`, `server/`)의 계산·동기화·보안 부분, git 커밋·푸시, 구글 로그인. 이건 Claude가 직접 하거나 검토 에이전트를 거친다.

## 순서
1. **지시서 쓰기** — `docs/design/briefs/<이름>.md` (시안이 아니면 `logs/gemini/briefs/`). 짧고 구체적으로:
   - 목표, 만들 파일 경로와 이름, 참고할 기존 파일(제미나이가 직접 읽게 경로만 적는다. 내용을 붙여 넣지 않는다)
   - 지켜야 할 기준: `CLAUDE.md`의 UI 방향, `docs/design/README.md`의 색 기준값, `docs/FEATURES.md`의 기능 누락 금지
   - 화면 크기, 예시 데이터, 끝났을 때의 모습(완료 조건)
2. **실행** — 오래 걸리므로 백그라운드로 돌린다:
   `bash tools/gemini.sh <지시서> <허용 폴더> [모델]`
   - 허용 폴더 밖이 바뀌면 스크립트가 경고하고 실패(코드 3)로 끝난다. 그때는 바뀐 파일을 확인하고 되돌릴지 사용자에게 묻는다.
   - 모델 기본값 `gemini-4-neon-high`. 바꾸려면 세 번째 인자나 `GEMINI_MODEL`. 목록은 `~/.gemini/bin/agy.exe models`.
   - 제미나이는 **터미널 명령을 쓰면 안 된다**(무인 실행이라 자동 거부되고 빈 응답으로 끝남). 스크립트가 이 규칙을 붙이고, 빈 응답이면 실패(코드 4)로 끝낸다.
   - 진행 상황은 협업 센터 `npm run collab`(http://127.0.0.1:8787)으로 사용자가 직접 볼 수 있다. 사용자가 센터 입력창으로 Claude·제미나이에게 직접 일을 줄 수도 있다(CLAUDE.md "협업 센터"). 검토 결과는 `logs/gemini/review.md`에 적으면 상황판에 보인다.
   - 응답 전문은 `logs/gemini/*.log`(git 제외). 화면에는 끝 25줄만 나온다.
3. **검토(Claude)** — 파일 전체를 읽지 말고:
   - `git status`, `wc -c`로 파일이 다 생겼는지
   - 브라우저(스크린샷)로 화면을 보고, 필요한 부분만 `grep`으로 확인
   - FEATURES.md 기능이 빠졌는지, 색·아이콘 기준을 지켰는지, 외부 스크립트·추적 코드가 없는지
4. **고칠 점이 있으면** 고칠 점만 적은 짧은 지시서로 다시 제미나이에게 맡긴다. 아주 작은 수정(몇 줄)만 Claude가 직접 한다.
5. 결과를 사용자에게 알리고, 커밋은 Claude가 한국어로 한다.

## 새 컴퓨터에서
- Antigravity(agy)를 설치하고 한 번 로그인해 두면 된다. 스크립트는 PATH의 `agy`나 `~/.gemini/bin/agy.exe`를 찾는다.
- 로그인은 사용자가 직접 한다(Claude가 대신하지 않는다).
